# HTTPS + PWA 완전 설치 (DSM 7.1 기준)

LAN http로는 태블릿 홈 화면 추가가 "바로가기"(주소창 보임)까지만 된다.
https를 붙이면 **주소창 없는 전체화면 앱(PWA standalone)** 으로 설치된다.

코드는 이미 준비돼 있다 (`public/manifest.json`의 `display: standalone` + 아이콘,
`src/app/+html.tsx`의 매니페스트 연결). 이 문서는 전부 DSM 설정이다.

## 최종 구조

```
외부(친구들) → 라우터(443→5001) ──────────→ DSM            ← 기존 그대로, 안 건드림
LAN          → https://<DDNS도메인>        → DSM            ← NAS 443 기본 서버가 :5001로 넘김
LAN          → https://<DDNS도메인>:8088   → 역방향 프록시  → localhost:8089 MeePick
LAN          → http://<NAS IP>:8089        → 컨테이너 직결  ← 비상용
```

전제가 된 이 집의 네트워크 사정:

- DDNS(`zzanzzan.synology.me`)와 Let's Encrypt 인증서는 이미 있다 (DSM 자동 갱신).
- **라우터의 외부 443은 `→ NAS 5001` 포워딩으로 이미 쓰인다** — 친구들이 포트 없는
  주소로 DSM(파일 공유)에 들어오는 길. 그래서 MeePick은 별도 포트(8088)를 쓴다.
- U+ 공유기는 **NAT 루프백이 안 된다** — LAN에서 공인 IP 경유 접속 불가.
  그래서 LAN 전용 DNS(아래 3)가 도메인을 NAS로 직행시킨다.
- **라우터에서 8088·8089를 포워딩하지 않는다.** MeePick이 LAN 전용인 근거다.

## 1. 컨테이너 포트 — 8089

`deploy/nas/docker-compose.yml`이 `8089:80`으로 바인딩한다. 8088은 DSM 역방향
프록시가 차지하므로 컨테이너가 쓸 수 없다.

## 2. 역방향 프록시 (제어판 → 로그인 포털 → 고급 탭 → 역방향 프록시)

| | 값 |
|---|---|
| 소스 | HTTPS / `zzanzzan.synology.me` / **8088** / HSTS 체크 안 함 |
| 대상 | HTTP / `localhost` / **8089** |

저장 후 **제어판 → 보안 → 인증서 → 설정**에서 이 항목에 LE 인증서가
매핑돼 있는지 확인 (보통 자동).

## 3. LAN에서 도메인을 NAS로 해석 — DNS Server

헤어핀이 안 되므로 LAN 기기가 `zzanzzan.synology.me:8088`을 열려면
LAN 전용 DNS가 그 도메인을 NAS IP로 답해 줘야 한다.

1. **패키지 센터 → DNS Server 설치** → 실행
2. **영역(Zones) → 생성 → 마스터 영역**: 정방향 / 도메인 이름 `zzanzzan.synology.me`
   / 마스터 DNS 서버 `192.168.219.112`
3. 만든 영역 더블클릭 → **A 레코드 생성**: 이름 비움(도메인 자체) / IP `192.168.219.112`
4. **확인자(Resolution) 탭 → 확인 서비스 활성화** + 전달자 `8.8.8.8`, `1.1.1.1`
   (영역 밖 모든 도메인은 인터넷 DNS로 넘어간다)
5. 공유기 DHCP의 DNS를 NAS로: U+ 공유기 **고급설정 → 네트워크 → DHCP 서버**에서
   기본 DNS `192.168.219.112`, 보조는 비움 — 보조를 넣으면 기기가 가끔 그쪽으로
   물어봐서 도메인이 공인 IP로 풀리고, 그 순간 :8088은 안 열린다
6. 기기 Wi-Fi를 껐다 켜서 DHCP 갱신

바꿔도 bare 도메인은 여전히 DSM이다 — LAN에서는 NAS의 443 기본 서버가 :5001로
넘겨주고, 외부는 애초에 공인 DNS를 쓴다.

**대가:** NAS가 LAN 전체의 DNS가 된다. NAS가 꺼지면 집 인터넷 이름 해석이 죽는다 —
NAS 24시간 가동이 전제다 (원래 그렇게 쓰고 있다).

## 4. 방화벽 (제어판 → 보안 → 방화벽)

"해외 접속 차단" 프로필(남한 허용 + 기본 거부) 기준으로 필요한 규칙 하나:

| 포트 | 소스 | 동작 |
|---|---|---|
| 모두 | 서브넷 `192.168.219.0/255.255.255.0` | 허용 |

GeoIP "남한" 규칙은 **사설 IP를 매칭하지 못하므로** 이 규칙이 없으면 LAN 트래픽이
기본 거부에 걸린다 (SSH가 갑자기 막히는 원인이 이것이었다).

## 5. 외부 공개 (선택)

밖에서도 열리게 하려면 이 단계까지 한다. **전제: 쓰기 잠금이 먼저다** —
`supabase/migrations/20260821090000_auth_write_lock.sql`과 SUPABASE_SETUP.md 7-1
(공용 계정 + 가입 차단)이 적용돼 있어야 한다. 잠금 없이 열면 방문자 누구나
번들의 anon 키로 데이터를 수정할 수 있다.

- 라우터 포트포워딩 추가: **외부 TCP 8088 → NAS IP:8088**
  (외부 443은 DSM 파일 공유 통로라 건드리지 않는다)
- 접속 주소는 안팎이 같다: `https://<DDNS도메인>:8088`
  - 밖: 공인 DNS → 집 공인 IP → 라우터(8088) → DSM 프록시
  - 안: LAN DNS → NAS 직행 (헤어핀 불가 공유기라 이 경로가 따로 있다)
- DSM 방화벽의 "남한 허용 + 기본 거부" 프로필이 그대로 적용된다 — 해외 IP는 차단.
- 검색엔진 노출은 없다 — 웹 셸에 `noindex`가 박혀 있다. 링크를 아는 사람만 본다.
- 공개 후에도 조회만 가능하고, 기록·수정은 상단 🔒 로그인(공용 계정)이 필요하다.

## 6. 태블릿 설치

1. 기존 http 홈 화면 바로가기 삭제
2. Chrome에서 `https://zzanzzan.synology.me:8088` 접속 — 자물쇠 확인
3. 메뉴(⋮) → **"앱 설치"** (또는 "홈 화면에 추가")
4. 실행하면 주소창 없는 전체화면으로 뜬다

## 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| :8088이 안 열림 (시간초과) | 기기가 아직 옛 DNS — 도메인이 공인 IP로 풀림 | Wi-Fi 재연결(DHCP 갱신), 공유기 DHCP DNS 확인 |
| 인증서 경고 | RP 항목에 자체서명 인증서 매핑 | 제어판 → 보안 → 인증서 → 설정에서 LE로 변경 |
| "앱 설치" 메뉴가 없음 | http 접속이거나 인증서 오류 | 주소·자물쇠 확인 후 새로고침 |
| RP가 죽어 https가 안 열림 | DSM nginx 문제 | 비상용 `http://<NAS IP>:8089`로 접속, DSM 재시작 |
| 인증서 갱신 실패 알림 | LE 갱신 경로 문제 | 반복될 때만 라우터 80을 NAS로 임시 포워딩 후 수동 갱신 |
